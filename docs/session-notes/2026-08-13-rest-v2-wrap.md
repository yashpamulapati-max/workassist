# Work Assist — REST V2 wrap (2026-08-13)

## Why not 205 separate tools

Swagger V2 has **154 paths / 205 operations**. Registering each as an iframe SDK tool would
re-trigger the Zod `onBeforeRun` failure (whole tool set discarded). Instead the parent wraps
the **entire spec** as a catalog + generic caller.

## What shipped on yp2

Same-origin fetch of `/ams-web/openapi/v2/openapi.json` (no ngrok). User’s TID token from `GVars`.

| Tool | Role |
| ---- | ---- |
| `list_api_endpoints` | Search catalog by keyword/tag |
| `describe_api_endpoint` | Params + request body for one method+path |
| `agile_assets_api` | GET/POST/PUT/DELETE relative to `/rest/v2/` |
| `dom_get_required_fields` | DataWindow required flags for **Save on this screen** |

Responses include HTTP status and are truncated if huge so the agent service does not 422.

## “Unprocessable Content” (resolved 2026-08-13 / 08-14)

Root cause (from the agents run API, **not** the model picker):

```
HTTP 422: body.context: List should have at most 10 items after validation, not 14
```

`runContext.context` must be **≤ 10 items**. Studio worked because it never attached the iframe
host-tool payload. Haiku in the embed 422’d for the same reason.

Also: do not duplicate agent MCP tool names in `onBeforeRun`; no-arg tools must omit `parameters`;
Kernel JS must be cache-busted (`?v=` on `w_main.jsp`). See
[2026-08-14 persist and 422](./2026-08-14-persist-and-422.md).

Save-required questions still use `dom_get_required_fields` (this screen’s DataWindow flags), not REST.
